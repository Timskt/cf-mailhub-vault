# 可切换数据源与服务器迁移

状态：已实现并完成本地多数据库集成测试。数据库接入不修改现有生产配置，也不会自动连接真实服务器。

## 决策

数据源是独立实例，不是数据库类型。允许多个 MySQL、多个 MongoDB、多个 Redis，以及 D1；同类实例和跨类型实例使用相同迁移协议。业务层使用结构化查询、行变更和稳定主键，不再向具体数据库发送 SQLite SQL。

Cloudflare Durable Object 为一个工作区提供唯一写入协调器，保存数据源配置、切换状态和可恢复的写入意图。D1 是可选的数据存储；远程数据源通过自托管 HTTPS connector 接入，数据库账号仅存在于 connector 的服务器环境中。连接令牌在协调器里使用独立密钥加密，API 不返回令牌。

MySQL、MongoDB、Redis 保存 MailHub 管理的结构化记录与版本元数据。MySQL 使用 InnoDB JSON 表，MongoDB 使用集合与事务，Redis 使用持久化单 Hash 及 Lua 校验后的单条 HSET 原子提交。统一格式允许跨类型复制；这是应用管理的数据集，不是任意业务库的通用迁移器。Redis 主存储要求 AOF、always fsync、noeviction；MongoDB 要求副本集。

## 切换协议

1. 在目标实例创建新的隔离数据集，不覆盖已有数据。
2. 记录起始版本，分页复制所有表；原实例继续服务。
3. 重放复制期间的所有写入，包括删除、令牌轮换、登录设置和 ID 序列。
4. 短暂暂停应用写入，追平最后变更，逐页比较内容摘要和序列。
5. 校验一致后持久化新的活动数据源，恢复写入。读取和设置页面可在写入暂停时使用。
6. 原数据集保留。切回旧服务器也先重新同步，不能直接读取过时副本。

写入先保存意图，再以期望版本原子提交到主库。响应丢失时通过提交摘要识别重复，不重复分配 ID。后台 alarm 持续复制，不依赖浏览器保持打开；失败可重试和恢复，未切换前原实例保持权威。禁止两个控制器同时接管同一数据集，也不在主库故障时默默读旧副本。

## 边界

这是单工作区、单写入者的管理平台。所有写入必须经过应用；直接用数据库客户端改业务记录不会进入增量日志。连接服务必须通过 HTTPS、Tunnel 或受控内网访问。数据库服务器 A → B 的迁移包含应用数据；DNS、Worker Secrets、Microsoft 应用配置、TLS 证书不属于数据库内容，需要在部署层配置。跨 Cloudflare 账号的协调器搬迁需要独立交接流程，不能以数据库同步替代。

大数据集采用有界分页；Redis 查询需要扫描，适合有限规模工作区。迁移目标需要容纳完整数据集，源需要保留迁移期间的变更日志。没有承诺任意规模零停写切换。
