# 收件规则与邮箱分配

这一版把域名收件箱、规则和批量邮箱串成完整流程。入口是侧栏的「收件规则」、「域名收件箱」和「临时邮箱」。

## 常见用法

### 为不同用途分配独立邮箱

在「临时邮箱 → 批量分配邮箱」选择一个或多个已接入域名、总数量、用途前缀、有效期和备注。例如前缀 `shopping`、备注「购物账号专用」，一次分配 20 个地址，依次用于不同商店。地址会轮流分配到选中的域名，并追加序号和随机后缀。

先预览完整清单；预览按域名统计分配数量，并以编号表格显示地址，预览不写入数据。可选常用数量或输入 1–100 的总数，也可一次全选或清空域名。确认创建后整批写入，任何地址冲突或域名无效都不会留下部分新建记录。成功页支持复制所有地址与导出 JSON 清单。若提交期间网络断开，先刷新列表核对结果，再重试；重复提交相同地址会被拒绝。

列表支持按用途备注搜索、编辑用途，显示已有邮件总数、未读数和最近来信时间。统计基于当前保留的邮件，邮件清理后会相应变化。永久邮箱及绑定平台的地址继续沿用原有保护规则。

### 自动整理来信

新来信默认进行本地模式识别：验证码 / 验证链接、账单 / 收据、订阅 / 简报、通知提醒、普通邮件。识别使用邮件中已提取的验证码和保守的主题关键词，不调用外部 AI；可能需要手动修正分类。

在「收件规则」建立规则：

- 条件支持发件地址包含、主题包含、指定收件地址、收件域名、仅匹配验证码 / 验证链接邮件。填写的条件须全部满足，文本按字面匹配，不执行正则表达式。
- 动作支持设置分类、标为已读、归档、置顶，可组合使用。
- 数字优先级越小越先执行，相同优先级按创建顺序。每封新来信仅执行第一条匹配的启用规则。
- 至少设置一个条件和一个动作；单工作区最多 50 条规则。
- 从域名收件箱每封邮件的菜单选择「按发件人创建规则」，可直接带入发件地址。

规则只处理域名收件箱。Outlook 仍通过微软接口读取，当前没有后台扫描所有 Outlook 邮箱并执行这些规则。

### 预览后整理历史邮件

编辑器内的「预览命中」只展示匹配结果。保存规则也不修改历史邮件。需要整理旧邮件时，使用规则卡片的「预览 / 应用历史邮件」，确认后仅处理预览中的 ID。

预览返回匹配总数并最多展示最新 100 封。应用时再次校验条件与规则版本；规则被编辑、停用或删除时会要求重新预览，不使用旧规则继续写入。手动应用只执行所选规则，不受其他规则优先级影响。删除规则不撤销已经整理的邮件。

### 日常收件箱整理

「收件箱 / 已归档 / 全部邮件」切换视图；可叠加分类、域名、地址、未读和验证码筛选。本页多选后，可以批量归档、移回收件箱、设置已读 / 未读、置顶 / 取消置顶或分类。切换页码和筛选会清空选择，避免误处理另一页的邮件。

**归档只改变所在视图，不延长保留期限。** 重要邮件可置顶防止自动清理，或将邮箱设为永久保留。验证码查收和兼容 API 继续能找到归档邮件；读取验证码不会把邮件标为已读。

## API

所有新增接口均要求管理员会话或 API Key，且拒绝跨站写入。完整接口表可从 `/api-doc.json`、`/api-doc.md` 读取。

| 接口                                | 主要参数 / 返回                                                                                   |
| ----------------------------------- | ------------------------------------------------------------------------------------------------- |
| `POST /api/mailboxes/batch-preview` | `domains`, `count`（1–100）, `prefix`, `remark`, `duration_minutes`, `is_permanent`；返回预览数组 |
| `POST /api/mailboxes/batch`         | `{mailboxes: 预览数组}`；整批创建                                                                 |
| `PATCH /api/mailboxes/:id`          | `{remark: "用途"}`                                                                                |
| `GET /api/cf-mails`                 | 新增 `folder=all/inbox/archived`, `category`；默认 `all` 保持已有 API 行为；页面默认 `inbox`      |
| `PATCH /api/cf-mails/:id`           | 布尔字段 `is_pinned`, `is_read`, `is_archived`；以及 `category`                                   |
| `POST /api/cf-mails/batch`          | `{ids: [...], patch: {...}}`，1–100 个 ID                                                         |
| `GET / POST /api/mail-rules`        | 列出规则 / 新建规则                                                                               |
| `PUT / DELETE /api/mail-rules/:id`  | 编辑完整规则 / 删除规则                                                                           |
| `POST /api/mail-rules/preview`      | 规则草稿；返回摘要，不写入                                                                        |
| `POST /api/mail-rules/:id/preview`  | 返回 `mails`, `total`, `limited`, `revision`, `changes`                                           |
| `POST /api/mail-rules/:id/apply`    | `{ids: [...], revision: "预览版本"}`                                                              |

分类枚举：`general`, `verification`, `billing`, `newsletter`, `notification`。

规则示例：

```json
{
  "name": "购物账单归档",
  "enabled": true,
  "priority": 20,
  "sender_contains": "@store.example",
  "subject_contains": "invoice",
  "domain": "mail.example.com",
  "recipient": "",
  "verification_only": false,
  "action_category": "billing",
  "mark_read": false,
  "archive": true,
  "pin": true
}
```

## 数据升级与边界

`0006_mail_workflows.sql` 只新增邮件的 `is_archived/category/rule_name` 字段和 `mail_rules` 表，不重写原有邮件内容或账号凭据。原有邮件保留普通分类，可手动整理。

新的规则及状态参与原有数据迁移与副本同步。旧的便携数据集在 D1 JSON、MySQL、MongoDB、Redis 中读取时补充默认值；原始快照内容及校验哈希保持不变。自建 HTTP Connector 需要一同更新代码后再使用新功能；当前生产的 Redis 直连由 Worker 内置适配器更新。

单次批处理受原有 8 MiB 事务上限限制，包含很大正文的邮件应减少每批选择数量。Redis 副本仍是手动同步的时间点快照，新增规则不会让它自动变成持续复制。

## 验证

- MIME 来信分类、首条匹配、重复投递与手动状态保留。
- 草稿预览无写入、规则变更检测、事务内版本检查、停用规则拒绝执行、历史预览上限和认证。
- 邮件批量状态可逆且不覆盖无关字段；批量邮箱校验失败无部分写入，并发地址冲突只有一次成功。
- MySQL、MongoDB、Redis 旧数据查询与新规则往返 D1；原有完整跨库切换集成测试。
- 浏览器操作覆盖规则 CRUD、开关、历史应用；收件箱批量处理；跨域名分配、复制、导出与用途编辑。弹窗和页面在 1440×1000、375×667、844×390 检查布局。
