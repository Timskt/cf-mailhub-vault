# 验证码与验证链接快捷查收

2026-11-15 更新。

## 使用方式

- **Outlook / 平台账号 / 临时邮箱**：在列表点击「取码 / 链接」，结果直接显示在当前页面。默认查最近 24 小时，可改为最近 10 分钟、1 小时或不限时间的近期邮件，也可限定发件人和关键词。
- **邮件列表**：Outlook 和域名邮件列表直接显示已识别的验证码与验证链接，支持复制；链接显示为可点击操作，不自动访问。
- **等待新邮件**：从点击时刻开始，只查后续收到的邮件，每 8 秒检查一次，最多 3 分钟。找到结果、遇到错误、超时或手动停止时结束。页面隐藏期间暂停定时请求，关闭查收面板或离开页面会清理请求及计时器。
- **域名收件箱**：「只看验证码 / 链接」筛选收件时已识别的邮件；取码、复制不会将邮件标记为已读。
- **平台账号历史验证码**：明确标记为历史，并显示原收件时间。验证码是否过期由目标平台决定。

## 实现与边界

提取器识别中英文上下文、4–8 位数字、常见大写字母数字码、分组码、HTML 实体，以及带有验证/登录语义的按钮链接。要求上下文，避免将一般订单号、CSS 颜色、年份或 URL 参数当作验证码。识别是启发式规则，无法保证覆盖每一种邮件模板。保留原邮件供阅读。

Outlook 取码首先分别读取收件箱和垃圾邮件各 10 封。只有后续页仍可能包含更新的匹配结果时才继续读取，每个文件夹最多再请求 15 封。时间过滤在无关键词时发送给 Graph，同时在本地复核；带关键词时保留 Graph 的搜索排序，再应用本地过滤。任一必要请求失败时返回实际错误，不将部分成功包装成空邮箱或完整结果。列表在服务端提取后只返回摘要和识别结果，不向浏览器批量传输完整正文。

本次没有新增持久化缓存或表结构。短期结果仅存在当前页面状态，减少旧验证码被当成新结果的风险。域名邮件列表沿用邮件到达时保存的识别结果，已有邮件在快捷查收时也会重新尝试解析正文；「只看验证码 / 链接」不重新扫描所有历史正文。

## API

- `GET /api/outlook/accounts/:id/code`
- `GET /api/vault/:id/code`
- `GET /api/mailboxes/:id/code`（新增）

以上均支持 `since`（ISO 日期）、`sender`、`q`，返回 `code`、`link`、邮件主题、发件人、收件时间、`scanned`、`checked_at`；到扫描上限时可返回 `limited`。

`GET /api/outlook/accounts/:id/emails` 增加 `verification_code`、`verification_link`；`GET /api/cf-mails` 增加 `verification_link` 并支持 `verification=true` 筛选。

## 验证记录

- 54 项自动化测试通过。新增提取器和接口回归覆盖代码格式、链接实体/安全协议、误报、分批查询、垃圾箱较新结果、上游限流、列表字段、时间和发件人过滤、未读状态保留。
- 浏览器验证了 Outlook、平台账号、临时邮箱的直接查收入口，以及复制码/链接、筛选、等待新邮件、停止、超时、错误重试、后台暂停和离开页面清理。
- Outlook 收件弹窗、嵌套取码弹窗、数据源卡片检查了 1440×1000、375×667、844×390；域名收件箱检查了桌面和手机。
- 浏览器收到新验证码、错误等确定性场景采用虚构 API 响应；存储 D1 连接测试使用本地真实接口。生产邮箱另行只读验证，不打开其验证链接。
