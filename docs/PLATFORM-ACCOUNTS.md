# 平台账号：概览、抽屉与连接状态

平台账号首页按平台名称汇总，同名平台不区分大小写。首页展示平台总数、账号总数、需要处理和待检查数量；一个 Outlook 平台无论有多少账号，都只占一张平台卡片。

「邮箱资产」提供邮箱视角，一个邮箱可登记多个平台，每个平台保留各自的密码、2FA、登录方式和生命周期。设计来源与验收基线见 [一邮箱多平台注册需求调研](MULTI-PLATFORM-IDENTITY-REQUIREMENTS.md)；该调研保留其编写时的背景与拟新增能力，当前功能以本文及 [API 契约](API.md) 为准，不据此推断生产部署状态。

## 邮箱资产与平台注册

邮箱资产按实际收件地址与来源聚合，包含已接入的邮箱连接，以及已登记但未接入的邮箱。同一个地址的不同来源是不同身份。列表支持按地址/平台名搜索、来源筛选和分页；顶部概览统计整个工作区，展示平台、独立地址、注册、连接、需处理连接、受影响登记及已到期/七天内到期登记数，不随列表筛选变化。

点击邮箱打开详情，分页查看全部平台注册和连接概览，可复用此邮箱登记另一个平台、查看保护影响，或前往对应来源管理连接。连接凭据在 Outlook/provider 账号中维护一次，不复制成各个平台的登录密码；注册列表不返回密码或 2FA 密钥。

登记和编辑支持工作区、账号标识、登录方式、实际收件地址、连接状态、平台验证规则，以及登记/最近核验/到期日期。`account_email` 是平台登录邮箱，`mailbox_address` 是实际收件邮箱，空值回退账号邮箱；别名必须显式映射。登录方式可为密码、Google、Microsoft、SSO、邮件链接、通行密钥或未知；未知日期留空，不推断。

`mailbox_link_state=detached` 表示主动解除此平台注册的收件连接：保留台账、平台凭据及现有邮件保留保护，自动查收返回 `MAILBOX_DETACHED`。重新按地址发现身份不会解除该状态。连接故障在邮箱身份中汇总，受影响登记数排除 detached；平台注册自己的手动状态仍独立维护。

## 独立平台管理

首页「新建平台」可先保存名称、官网、分类、备注和平台置顶，无需先登记账号。「管理平台」提供搜索、编辑、打开账号抽屉、合并与删除。零账号的平台继续保留，计入平台总数。

重命名在同一事务中更新关联账号和邮箱绑定，保留密码、2FA、账号状态与备注。名称已存在时应使用「合并平台」：全部账号转入目标，保留目标平台资料；即使邮箱和用户名相同，也保留两条记录供人工核对。平台有账号时禁用删除，服务端也拒绝直接删除，防止误清空账号。

平台分类与账号分类分别保存；编辑平台资料不会覆盖每个账号的分类、官网等个性化字段。登记新账号时选择已有平台，会预填其名称、官网和分类。

点击卡片进入平台详情抽屉。支持平台内搜索、按处理状态筛选、每页 20 条、置顶、编辑、复制、登记新账号与删除确认。首页每页 24 个平台，可按名称、账号数量、需要处理数量或置顶账号数量排序。平台统计不再截断为前 50 个。

## 批量整理与敏感操作

平台抽屉支持卡片与紧凑表格，选择会记住跨页项目，最多 100 个。批量分类、状态、备注和置顶原子处理；失败保留选择和输入，成功后刷新。单账号、已选账号、整个平台及首页筛选结果均可导出。导出弹窗先展示格式模板，点击「生成导出内容」才读取凭据；支持固定文本、CSV、JSON、复制和下载，所选账号已失效时明确报错。格式与导入规则见 [账号导入导出](ACCOUNT-TRANSFER.md)。

列表只提供 `has_totp` 标记。明确打开动态口令时才读取密钥，在浏览器按 RFC 6238 计算 SHA-1/256/512、6/8 位口令；切到后台或两分钟后隐藏。编辑支持严格校验的 Base32/otpauth URI，二维码识别取决于浏览器 BarcodeDetector 支持，缺少能力时提供文本输入。密码生成使用密码学随机数，不依赖外部服务。

邮件详情可打开对应来源与收件地址的邮箱身份并查看关联平台注册；CF 台账按有效收件地址定位，别名与登录邮箱可分别保留。查看凭据、TOTP 和导出需要相应权限，不能将列表标记当作可匿名获取密钥的接口。

## 两类状态分别维护

- **登记状态**：使用中、待验证、已封禁、已废弃，由管理员手动维护。使用中不表示平台登录或邮箱连接经过验证。
- **邮箱状态**：从当前 Outlook/provider 账号池、最近连接检查、续期结果和收件域名配置派生，按实际收件地址与来源匹配。列表读取不发起远端连接检查，也不会修改登记状态。

| 情况                               | 显示                        | 处理入口                                   |
| ---------------------------------- | --------------------------- | ------------------------------------------ |
| 台账的 Outlook 邮箱不在账号池      | 邮箱未接入                  | 接入此 Outlook 邮箱，带入邮箱地址          |
| Outlook 账号停用                   | 邮箱已停用                  | 管理邮箱连接                               |
| 微软授权失效                       | 邮箱需重新授权              | 管理邮箱连接，重新授权或更新凭据           |
| 最近续期或收件失败                 | 邮箱续期异常 / 邮箱连接异常 | 检查邮箱连接、管理邮箱连接                 |
| 导入后尚未验证                     | 邮箱待检查                  | 检查邮箱连接                               |
| 收件检查成功已超过 24 小时         | 邮箱需复查                  | 检查邮箱连接                               |
| 最近 24 小时内收件检查成功         | 邮箱已连接，附检查时间      | 查收、复查、管理连接                       |
| Mail.tm / Mail.gw 未接入或连接异常 | 对应 provider 连接问题      | 接入或管理对应来源连接，检查邮箱           |
| 此平台注册主动解除收件连接         | 收件连接已解除              | 核对并编辑此平台注册的关联状态             |
| CF 临时邮箱已过期且无保留保护      | 邮箱已过期 / 停用           | 新邮件将被拒收，仍可查询已保存邮件         |
| 自建域名缺失、停用或 DNS 不完整    | 对应域名问题                | 检查收件域名；仍可查询已保存邮件           |
| 自建域名 DNS 就绪                  | 收件 DNS 已就绪             | 查询已保存邮件；新邮件仍依赖 Email Routing |
| 外部或公共邮箱                     | 外部邮箱 · 手动查收         | 在原服务商查收                             |

“需要处理”统计邮箱明确有问题，或手动标记为待验证/已封禁的账号；“待检查 / 复查”统计尚未确认连接或检查已超过 24 小时的账号。两个数可能有交集，例如登记为待验证且邮箱尚未检查。统计单位均为平台账号，同一个邮箱绑定多个平台账号时分别计数。

已过期且无保留保护的 CF 邮箱身份在列表及详情中返回 `health.state=disabled`、`health.can_lookup=true`。此状态表示停止接收新邮件，已保存的历史邮件仍可查收。

## 搜索与返回

首页搜索匹配平台名、邮箱、用户名、备注和历史验证码。筛选后的卡片显示匹配账号数；顶部概览仍显示整个工作区的总量。打开抽屉沿用筛选，提供“查看此平台全部账号”以恢复该平台全量列表。

快捷查收在独立弹窗中展示验证码、验证链接、等待新邮件与筛选。平台模式按显式发件人/关键词或登记规则匹配，缺少规则时提示配置，也可明确选择「查整个邮箱」。整个邮箱的结果会标明可能属于其他平台，不更新平台历史验证码；平台模式找到验证码后，在保存历史前核对目标、收件关联及验证规则。查询期间发生变化时返回 `409 STALE_PREVIEW`，不保存本次历史验证码；刷新台账、核对当前规则后重新查收。匹配规则用于帮助核对，不提供共用邮箱中的邮件隔离。

API 的 `match` 默认为 mailbox，以兼容原调用；`match=platform` 要求 `vault_id` 或唯一平台且有规则，无规则返回 `VERIFICATION_RULE_REQUIRED`，直接邮箱目标返回 `PLATFORM_TARGET_REQUIRED`。台账目标返回 `match_scope`、`match_reason`，不会自动回退整个邮箱。结束查询后刷新账号连接状态；关闭只退出当前弹窗，保留平台抽屉和筛选位置。异常处理跳转到 Outlook 时自动搜索对应邮箱；缺失账号可预填邮箱后添加凭据，或使用现有批量导入/微软授权。提供返回关联平台账号入口。

旧 `GET /api/external/code?platform=...` 按唯一平台注册的有效收件地址（`mailbox_address`，空则 `account_email`）及来源查收，检查 detached 状态；多账号、未找到、已解除连接分别返回 `409 AMBIGUOUS_TARGET`、`404 TARGET_NOT_FOUND`、`409 MAILBOX_DETACHED`。显式 `email` 始终优先并保持邮箱范围查询，不应用平台注册的验证规则或 detached 状态。旧接口按请求中的 `since/sender/q` 过滤，保留平铺响应且不更新平台历史验证码。

## API 与存储兼容

- `GET /api/vault`：保留分页与旧筛选，增加 `mailbox`、`needs_attention` 和 `triage=attention|unchecked|connected`。
- `GET /api/vault/platforms`：保留 `data` 数组，增加各平台统计和响应 `summary`。传 `page/limit` 才分页，不传时返回全部平台。`sort=name|count|attention|pinned`。
- `GET /api/vault/stats`：增加 `total_platforms`、`attention_accounts`、`unchecked_accounts`。原 `active_vault_accounts` 保持登记状态计数的含义。
- `GET/POST /api/platforms`：平台目录与独立创建，包含零账号平台。
- `PUT/DELETE /api/platforms/:name`：编辑、重命名或删除空平台，路径中的名称需 URL 编码。
- `POST /api/platforms/:name/merge`：以 `{ "target": "目标名称" }` 合并平台。
- `GET /api/mailbox-identities`：q/source/page/limit 查询身份；`total` 是筛选后数量，`summary` 为全局统计。
- `GET /api/mailbox-identities/{id}`、`/{id}/registrations`、`/{id}/impact`：身份详情、分页注册和保护影响；ID 是整体 URL 编码的 `source:小写地址`，不是数字 ID。全部按 admin collection 保护，资源受限 Key 即使指定 ID 或筛选也不能枚举。
- `POST /api/vault/import-preview`：文本/CSV/JSON 导入预览，返回行号、错误、action=create|update|skip、changed_fields、existing_id，不返回密码、2FA。
- `POST /api/vault/import`：duplicate_mode 默认 skip；更新默认 update_mode=merge 保留省略字段，明确 replace 才默认化省略字段。重复身份包含平台/账号邮箱/用户名/来源/工作区/账号标识/登录方式；首 11 文本列保留，追加 10 个元数据字段共 21 列。

独立平台目录使用 `0011_platforms.sql` 增量迁移，为旧 D1 台账建立平台资料；`0014_shared_registrations.sql` 增加平台注册元数据。D1、MySQL、MongoDB、Redis 使用同一事务与状态派生逻辑，旧数据缺少新字段时使用兼容默认值。当前便携业务备份为 schema 13，包含平台目录、provider 连接和注册元数据；兼容冻结投影严格校验后的 schema 10/11/12，升级时补齐新表及默认值。平台及邮箱身份管理要求管理员会话、主 API Key 或无资源限制的 `admin` 子密钥。汇总查询不读取密码、2FA 或 Refresh Token；账号列表仍去除凭据。

## 交付前主动检查

后续页面改动需覆盖以下场景，并记录实际结果，而不是等待用户反馈：

1. 同一平台有大量账号、存在多个平台、平台超过一页，统计是否仍准确且其它平台容易找到。
2. 新建、未关联、未检查、成功、失败、授权撤销、停用、删除再接入，状态与操作是否一致。
3. 搜索和筛选能否清除，跨页搜索是否重置页码，跳转处理后是否能返回原任务。
4. 操作是否产生真实结果；失败是否保留输入、支持重试，提交期间是否防止重复提交及误改输入。
5. 抽屉中的弹窗、菜单和确认框是否只关闭顶层；关闭后焦点是否回到合理位置；删除最后一条记录是否能恢复。
6. 1440×1000、375×667、844×390 下检查长文本、滚动、底部按钮、浅色与深色，不只测容器尺寸，也查看截图。
7. 生产只做已授权的验证，测试数据留在本地；验收结束关闭本任务创建的浏览器窗口、清理临时会话文件。

多平台关系、生命周期与凭据隔离的回归测试见 `tests/vault-health.test.ts`；实际远程数据库兼容测试见 `tests/storage.integration.ts`。
