# 全站交互与弹窗复核

日期：2026-11-15。

本次平台账号改版的主动检查流程、问题修复及验证结果见 [平台账号](PLATFORM-ACCOUNTS.md) 和 [增量验收](VERIFICATION.md#平台账号增量验收)。每次改动主动检查大量同类数据、多平台可见性、状态来源、失败恢复、嵌套层级、手机首屏密度和测试环境清理，并以实际操作结果与截图作为依据。

用户再次提供 Outlook 收件错误态截图后，本轮从实际按钮操作重新检查。前一轮 151 组检查证明了容器尺寸与滚动约束，遗漏了错误正文、重试按钮和面板内边距的组合问题，不能据此认定视觉验收完成。

## 验证方式

- Chromium 实际点击按钮、菜单项、页签、选择器、链接及确认操作，并核对 API 返回、持久化数据、剪贴板或下载文件。
- 新增、修改、删除、恢复、修改密码和数据库切换在 `localhost:8788` 的独立 Wrangler 数据目录 `/tmp/mailhub-clickpath-state` 中执行。全部账号、凭据、邮件和域名均为虚构数据。
- `localhost:8787` 用于现有预览的布局及失败状态复核。表单写入失败场景拦截请求，不保存模拟修改。
- 普通表单失败状态额外检查 1440×1000、375×667、844×390，共 39 组；另检查 320×568 下的复制失败提示。桌面、手机及深色邮件截图经过实际查看。
- 微软邮件成功响应、附件、授权回调、会话失效及同步暂停/重试使用明确的模拟响应；本地 CRUD、DNS 查询、密码变更、导出恢复和 Redis 迁移使用真实接口。真实微软服务无法连接的错误画面也已复现。

重复记录上的相同操作按共用处理函数归并；桌面表格与手机卡片入口分别点击。通过条件包含操作后的最终状态，不以“弹窗能打开”代替功能验证。

## 状态变化复核

- `Workspace.refresh` 递增数据版本，触发资源重新读取。列表刷新不再无条件重置 Outlook 勾选。
- `useResource` 在路径或版本变化时取消旧请求；不同查询的旧结果不显示在新查询中。
- `useAction` 防止重复提交；内联模式将失败交给当前表单展示，外层确认操作不会吞掉子请求错误。
- `ConfirmationDialog` 等待操作成功后关闭；失败保留当前层，底层阅读器或组织管理仍在。
- `clearSession` 取消在途请求并递增会话版本；JSON 请求与附件下载均核对版本，退出后不会交付旧会话结果。
