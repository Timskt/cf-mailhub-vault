## 首次更新：导入、续期与 Redis

四段 Outlook 文本本身能够导入。补充识别中文导出说明和中英文表头，预览明确区分「格式正确」与「已经保存」，按钮改为「确认导入」。兼容 Client ID 提示不再被呈现为格式错误。

真实账号导入成功后，发现 Worker 请求微软时使用了运行环境不支持的 `redirect: "error"`。修正为 `manual` 并拒绝跳转，真实连接检查及收件成功。新增真实 Workerd Request 构造器测试，覆盖此前 Node 模拟未能发现的问题。

进一步验证发现刷新请求未显式携带 `offline_access`，没有取得新的 Refresh Token。补齐后，用用户授权的真实账号取得并保存了新刷新令牌；线上执行续期任务再次验证令牌已轮换，成功 1、失败 0，随后真实收件成功。最近成功及下次续期在列表中显示，续期调度结果与手动执行入口已上线。详见 [OUTLOOK-RENEWAL.md](OUTLOOK-RENEWAL.md)。

Redis 增加直接填写 `redis://` / `rediss://` 的接入方式，复用 Connector 的数据模型与单 Hash 原子提交实现。连接 URI 加密保存，管理接口和页面仅返回去掉用户名、密码的地址。用户提供的 Redis Cloud 实例实测连接成功，但 AOF 为关闭状态，因此以「数据副本」接入。

线上 D1 → Redis Cloud 副本实际复制并校验 **19 条记录**，零重试；副本版本为 22，独立 Redis 客户端回读确认条数和版本一致，数据集没有设置 TTL。主库始终为原 D1。这是同步完成时刻的副本，后续变化需再次同步；免费实例的回收和缺少持久化仍可能导致副本丢失。
